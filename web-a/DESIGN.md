# Admin console design contract

Scope: preserve the existing admin component system for the OpenClaw updates console. Sources: `src/index.css`, `components/ui/`, `layout/admin-shell.tsx`, and `pages/broadcast.tsx`. This is not a redesign.

## 1. Atmosphere
Operational, warm, restrained. Platform administrators need to understand global scope and upgrade consequences before sending. Keep composition, review, pending, error, and confirmation distinct.

## 2. Color
Use existing semantic tokens only: background, foreground, card, muted-foreground, primary, border, input, ring, destructive. Preserve the current light/dark OKLCH palettes. No decorative accent borders or new colors.

## 3. Typography
Existing Inter body and Instrument Sans display stacks. Page title: `font-display text-2xl font-semibold tracking-tight`; section headings: `text-lg`; body and secondary copy follow the adjacent broadcast page. User content wraps and preserves line breaks.

## 4. Spacing and layout
Existing shell owns scrolling. Page: centered, full width, `max-w-3xl`, `gap-6`. Forms use `gap-5`, field groups `gap-2`, Card padding and native Tailwind spacing. Actions wrap on narrow screens; no nested scrolling region.

Layout: Organization admissions - inspect requests and their quotes in reading order -> stack (https://github.com/changeroa/StyleGallery/blob/main/patterns/stacking/stack.md); scroll owner: #main, with the existing desktop nav scrolling independently; anti-patterns: nested form scrollers, fixed actions and reordered focus. Quote fields use two columns at sm and one on mobile.

Layout: Settings - read profile, organization settings and credentials in order -> existing centered max-w-2xl stack (https://github.com/changeroa/StyleGallery/blob/main/patterns/stacking/stack.md); scroll owner: #main, with existing desktop navigation scrolling independently; anti-patterns: nested form scrollers, fixed actions and reordered focus.

## 5. Primitives and states
Settings merge: reuse the existing Card, PasswordField, Badge and Button primitives. Primary action: Update password; Session Sign out uses outline styling. Priorities: Profile, eligible organization settings, password/session. Required content: Name, Email, Role; existing SMTP and transfer policy fields/actions; Current password, New password, Confirm new password; validation, inline errors, temporary-password warning and Session/Sign out. Preserve global identity scope and owner-fenced replacement-token validation. Leave out separate Account navigation and duplicate credential screens. Forced settings prompts use the local change-password anchor; organization reads remain suppressed until the password requirement clears. Change password follows the organization sections, directly above Session.
Managed storage addition: preserve the existing review brief, primary Approve request action, quote grid and all decision/email states. Add the stored quote's `storage_limit_bytes` as exact GiB per agent and `max_file_size_bytes` as exact MiB per managed S3 file, with managed S3 uploads/files-only scope, direct guest workspace/local-write exclusion, and a stricter upload-tool limit caveat. Never substitute current-catalog values for the stored quote or imply a hard quota on the whole workspace. No new controls or visual tokens.
Reuse Button, Card, Input, Label and their existing variants. Native textarea follows broadcast styling; native radios form one labelled fieldset. Default selection is Optional. Review is a separate, focusable region. Pending locks all submission/edit actions. Before sending, save the immutable request in tab-local, admin-ID-scoped session storage; restore uncertain requests after navigation, reload or session replacement without automatic sending. Storage failures block sending. Clear only on confirmed success or an intentional new notice, with a duplicate-delivery warning; success shows server-returned notice and recipient count. Closing the tab ends recovery storage, so keep it open until confirmed.

Organization admissions reuse Card, Badge, Button, Select, Label and the native review textarea. Primary action: Approve request in the selected review. Priorities: submitted organization name and applicant email/requested tier, full quoted commercial snapshot, status and decision. Required content: submitted organization name (or "Organization name not provided" for nulls), applicant email, plan ID/name/currency, monthly price, annual price, included accounts, additional account monthly price, included agents, additional agent monthly price, the storage and workspace-disk add-ons (size and monthly price), maximum agents per account (Pro 2, Max 3, Ultra 5), requested/reviewed date, reviewer, saved review note, optional note, approve/reject, status filter, refresh/retry and previous/next pages. Quotes use the current OrganizationPlan contract and shared OrganizationAgentLimit enum; obsolete plan formats are rejected. Leave out metrics, billing and provisioning controls. Inline loading/error/empty/terminal feedback uses text; pending locks both decision buttons and the note. Only active genesis platform administrators enter this separate queue. Approval creates the named organization and its genesis administrator account and emails initial credentials to the applicant; the first sign-in requires a password change and payment remains separate. Requests without a name cannot be approved; rejection and resubmission with a name remain available. Preserve server conflict messages with return-to-requests and refresh guidance.

## 6. Motion

Approved organization reviews show the required nullable credential email status inline: pending means queued with no retry action, sent means SMTP accepted without claiming inbox delivery, failed shows the sanitized server error and Retry credentials email. Retry uses the same initial credentials and never creates another organization or changes its password; changed-password credentials cannot be resent. Null delivery has no email action. This action has its own session-fenced mutation/error, preserves the review decision, disables itself and Back while pending, and never polls. Refresh the list and reopen to read current status. No provisioned identifiers are displayed or inferred.
No new animations. Preserve shared button feedback; honor reduced motion with the existing transition/press overrides. Network work shows immediate textual progress without an indefinite decorative spinner.

## 7. Depth and radius
Use existing Card `rounded-2xl`, neutral one-pixel borders and `shadow-card`; fields and buttons retain `rounded-xl`. No new shadows, elevated layers, or modal surfaces.

## 8. Accessibility and constraints
Visible labels, linked help/errors, native keyboard radio behavior, 44px action heights, focus-visible rings, first-invalid-field focus, review-heading focus and live result/error feedback. Announce Optional/Mandatory consequences in text, not color. Preserve existing auth, platform-role and forced-password-change guards. No new dependencies or shared primitive changes; no newly accepted design debt.

## Transfer payment reviews
Preserve the admission pages' Card, Badge, Button, Label, native textarea and responsive `admission-content` typography. The shell owns scrolling; identifiers wrap and remain selectable. Keep the payment queue separate from destination admissions. Show immutable fee/instruction snapshots and explicitly distinguish admission creation from the final membership move. Approval requires a labelled, initially unchecked payment-verification checkbox; rejection is a separate destructive button with an optional bounded reason. Pending writes lock fields and both actions with immediate textual feedback; background reads preserve form focus. A successful user decision focuses its visible outcome heading. Loading, retryable error, empty and terminal outcomes remain inline. Access is fail-closed while the current tenant's default-organization capability is loading or unavailable; platform admins use the canonical platform guard. No additional visual tokens, animations or dependencies.

## Organization SMTP settings
Layout: [stack](https://github.com/changeroa/StyleGallery/blob/main/patterns/stacking/stack.md), preserving Settings' centered `max-w-2xl` vertical stack; shell `main` owns content scrolling, existing desktop navigation scrolls independently. SMTP fields form one column on mobile and two at `sm`; actions wrap. No nested form scroller, fixed actions, or shared layout changes.

Primary action: Save SMTP settings (within the SMTP form). Priorities: own organization and delivery state, connection fields, save/test/remove actions. Keep the platform Transfer fee and instructions section after SMTP and the unchanged Session/Sign out card last. Only an active genesis administrator with an admin role and own tenant membership sees SMTP; PA has no override or organization picker. Required controls: own organization, enable, sender email/name, SMTP host/port/username/password, implicit TLS, timeout, saved-source explanation, saved-password state, Save SMTP settings, Send test email, Remove SMTP configuration. Sender name may be blank and follows the saved server value, without a brand default. Organization delivery is isolated: disabled, missing or removed configuration means no organization email. Leave out decorative metrics, badges and new visual tokens. Use existing Card/Input/Label/Button, inline loading/error/status and native removal confirmation. Passwords remain masked, blank on load, local to the draft and omitted when blank; successful save clears plaintext. Force-password-change suppresses reads/actions. Scope-keyed remount discards drafts on membership change.

## Extra accounts and agents
Layout: [stack](https://github.com/changeroa/StyleGallery/blob/main/patterns/stacking/stack.md). Users gains one `h2` section ("Extra accounts and agents") between the platform admins and the company roster, in the page's `max-w-5xl` stack: two usage tiles (`sm:grid-cols-2`), the current renewal, open orders, the buy form, recent orders. The payment page, the review queue and the review detail use the transfer-payment pages' `admission-content` `max-w-3xl` stack. The shell owns scrolling; no nested scrollers, fixed actions or new tokens.

Primary actions: Place order (Users), Finish (payment page), Approve payment (review). Reuse Card, Badge, Button, Input, Label, Select and the native textarea and checkbox of the payment reviews; the file field is a native `input type="file"` with the Input border treatment. Status uses text plus a Badge variant (awaiting payment warning, sent for review soft, approved success, rejected destructive, cancelled and expired secondary), never colour alone.

Money: VND is shown with locale grouping and a `VND` suffix, USD with two decimals; the amount to transfer is the largest text on the payment page and has its own Copy button that copies bare digits. The Users preview computes the engine's amount (proration by remaining days, cents half up, dong up to the next thousand) from the overview with integers, and shows the prorated days, the full monthly price from next month and the resulting limits. Calendar dates are days, not instants, and never shift with the browser's time zone.

States: an uncapped company gets one sentence and no form; a platform admin sees usage and orders without the form; unset payment settings or an open purchase disable the form with the reason beside it and a link to the open order. Renewal copy distinguishes awaiting (pay by the 7th), lapsed (the 8th on), sent for review, paid and rejected. The payment page shows instructions only while awaiting payment; every other status is an outcome panel whose heading takes focus after an in-page transition, with the reviewer's note and the evidence preview. Cancel is an inline confirmation. Evidence previews load through the Bearer token, images inline and PDFs behind an "Open PDF" link, and revoke their object URLs on unmount. Approve needs the unchecked-by-default verification checkbox; reject needs a note of at most 1,000 characters. Settings (genesis platform admin only, on the review queue page) are one two-column form with a saved-rate line.

Accessibility: visible labels, linked hints and errors, `role="alert"` for field and request errors, `role="status"` for progress and copy feedback, Finish stays enabled and validates on submit with focus returned to the file field, 44px action heights, native file, checkbox and select controls.
