# tests

Root-level `test_*.py`, no shared `conftest.py`. Helpers include `agent_tools_catalog_fakes.py` and `openclaw_*_fixtures.py` in this directory. Prefer focused tests beside the contract being changed. Image build and OfficeCLI tests and smoke helpers live in the guest image project.

Run from `engine/`, not the monorepo root. Pytest has no `testpaths`; package-root `test_sandbox_config.py` is a print script, not a pytest module. OpenClaw node-pin tests need host Node `v26.13.0`; CI has no Node service. Guest: `node:26.13.0-bookworm-slim`; sandbox: `node:26.13.0-slim`; the guest image project's OfficeCLI smoke probe asserts container `v26.13.0`.

Inbound office parse: `test_document_parser.py`, `test_document_parser_routes.py`, binary `fixtures/anydoc/` (supported/malformed/encrypted/resource-limited/scanned). Do not mock anydoc for these cases. Route tests exercise storage-backed `read_document` for enterprise files and 10-50 MiB inputs.

## Commands

```bash
uv run pytest
uv run pytest tests/test_auth.py
uv run pytest -k "storage"
uv run pytest -x --tb=short
bash scripts/test.sh                      # whole suite; 90% branch gate on ten admin/auth/tenant modules; no argument forwarding
uv run pytest --cov=app --cov-fail-under=0  # optional full-app report, not the scoped gate
node --test tests/contract_codegen.test.mjs tests/contract_public_names.test.mjs  # offline codegen; manual, not in CI
(cd connectors/whatsapp && npm test)      # bridge node:test suite; builds first
```

## Conventions

- `asyncio_mode = "auto"` in `pyproject.toml`.
- Fakes live in the test file (`DummyResult`, `_FakePool`, `SimpleNamespace`).
- New DB tests wrap a fake raw connection and assert SQL / `%(name)s` params. Reset `_conn_ctx` and `reset_pool_for_tests()` when touching the pool.
- HTTP: `httpx.ASGITransport(app=app)` + `AsyncClient` when you need the stack; most tests call handlers directly.
- Clear `app.dependency_overrides` after use. Storage tests use `tmp_path`.

## Test Navigation And Coverage

- **Gate:** branch coverage with `fail_under=90` on the admin/tenant/auth surface (`app.api.admin`, `app.api.users`, `app.api.tenants`, `admin_provisioning`, `admin_audit`, `tenant_provisioning`, `tenant_lifecycle`, `platform_admin_seeder`, `admin_audit_dao`, `app.core.security`). Scope, terminal report, and fail-under are explicit in `./scripts/test.sh`, which selects no tests and forwards no arguments. Bare `uv run pytest` has no implicit coverage. CI adds XML/HTML reports via `PYTEST_ADDOPTS`.
- The 90% threshold applies only to that scoped gate; do not lower it or describe a full-app report as its result.
- Auth/A2A/tools dispatch, storage/sandbox helpers, logging, freeze scripts and schema text contracts have focused modules. `test_agent_tools_dispatch_contract.py` freezes names; `test_tool_seeder_tables.py` freezes catalog name-order.
- Modularization characterization: `test_okr_api.py` (handler-direct settings/lock/sync/owner/KR buckets), `test_feishu_inbound.py` (challenge / dedup / missing channel / group IDs).
- Genesis admin: `test_admin_genesis.py` - platform seeder (create / elevate-with-password / refuse / fail-closed), `must_change_password` gate, same-password reject, company create response mapping, register non-elevation. Tenant+admin write kwargs live in `test_tenant_create.py`. Additional-admin minting (genesis-only) lives in `test_admin_provisioning.py`.
- Runtime: `test_process_roles.py`, `test_runtime_*.py` cover normalized entrypoint decisions, bootstrap ordering, owned lifecycle/cancellation, readiness and proxy cleanup; `test_bootstrap_runner.py` covers schema-runner failures/cleanup. See `../app/runtime/AGENTS.md`.
- Fresh schema: `test_bootstrap_identity_schema.py` checks retired provider-department objects and the retained shared member columns. `test_bootstrap_schema.py` covers the wider DDL contract.
- Live PostgreSQL: `test_bootstrap_postgres.py` opts in with `BOOTSTRAP_TEST_DATABASE_URL`, creates a unique schema and drops it afterward. It asserts provider-sync table/column removal, retained member/relationship FKs and org department constraints. These tests skip when unset; fakes/text contracts do not prove live integration.
- Organization admissions: `test_organization_admissions_contract.py` (offline boundary, cipher binding) plus opt-in `BOOTSTRAP_TEST_DATABASE_URL` modules `test_organization_admissions_postgres.py` (submit/review/permissions), `test_organization_admission_provisioning_postgres.py` (atomic tenant + genesis admin + intent, replay/concurrency, conflicts/rollback, legacy rows), `test_organization_admission_email_postgres.py` (leased worker, backoff, retry, restart, obsolete credentials; fake `attempt_email`) and `test_organization_admission_smtp_postgres.py` (real `attempt_email` against a loopback capture server; platform SMTP only). Fixtures: `organization_admission_fixtures.py`.
- Tier agent cap (`../docs/organization-pricing.md`): `test_organization_plan_snapshots.py` (offline current snapshot and boundary rejection of the old wire format, undefined caps, mixed and extra fields), opt-in `MARACLAW_TEST_POSTGRES_DSN` modules `test_agent_tier_creation_postgres.py` (boundaries, administrators, explicit-destination platform admin, ambiguous/unreadable link, concurrent last slot, `effective_max_agents`) and `test_agent_tier_ownership_postgres.py` (transfer/handover, over-cap, create-vs-transfer race), plus opt-in `BOOTSTRAP_TEST_DATABASE_URL` `test_company_transfer_tier_postgres.py` (paid exact fit/atomic refusal, untiered, free). `tier_limit_fixtures.py` links a tenant to an approved admission with the current snapshot.
- Managed S3 storage quota (`../docs/managed-storage-quota.md`): opt-in `MARACLAW_TEST_POSTGRES_DSN` modules `test_managed_storage_{quota,ambiguity,conditions,tree,transfer,api}_postgres.py` (boundaries per tier, isolation, races, conflicts, overwrite, conditional edits, deletes, >1000-object tree delete, partial errors, ambiguity/cancel/restart/stale, ledger outage, pool saturation, transfer lock, real ASGI upload) and `BOOTSTRAP_TEST_DATABASE_URL` `test_company_transfer_storage_postgres.py`, all against `s3_wire_server.py` (loopback S3 with real botocore requests and scripted faults; fixture `managed_storage_fixtures.py` shrinks limits only inside tests); offline `test_storage_quota_outcomes.py`.
- Other `BOOTSTRAP_TEST_DATABASE_URL` opt-ins outside the CI job: `test_broadcast_email*_postgres.py` (incl. same-key broadcast race/replay) and `test_chat_sessions_postgres.py` (real router vs legacy list). Run them locally against disposable PostgreSQL; the scoped gate skips them.
- OpenClaw upgrades: `test_openclaw_update_executor.py` (fakes in `openclaw_update_fakes.py`: success, pull/start/readiness/publish failures, interrupted cutover, deleted/disabled agent), `_snapshot`, `_gates`, `_exclusion`, `_api`; `test_openclaw_update_postgres.py` (opt-in `BOOTSTRAP_TEST_DATABASE_URL`: fan-out matrix, replay, outstanding/gate semantics, publication CAS). Tests that call the gated seams or file routes patch the gate via `openclaw_update_gate_fixtures.py` or `assert_work_allowed`.
- Offline contracts: `test_api_contract_export.py` imports the real `app.main.app` and asserts the exporter never enters lifespan or touches DB/Redis; `--check` never writes. `contract_codegen.test.mjs` and `contract_public_names.test.mjs` compile the generated validators (no string snapshots) against the installed `web-e` Zod; `CONTRACT_ZOD_MODULE` (absolute filename) overrides it. No CI job runs the `.mjs` files; frontend CI runs only `npm run contracts:check`.
- WhatsApp bridge (`connectors/whatsapp/test/*.test.ts`, `node:test`): `npm test` compiles to `dist/test/` and lists files explicitly in `package.json`, so register new files there. Seams: `support.ts` (`ControlledTransport` fake Baileys transport, `ParentStore` fake parent credential RPC over the real `Peer`), `sdk-recovery.ts` (real Baileys `processMessage` and event buffer with inert stores) and `cli.test.ts` (spawns the real `dist/src/bridge.js`). Python parent counterparts: `test_whatsapp_personal_child_boundaries.py` (real `spawn_child` with a `PATH`-only environment; some cases need PostgreSQL), `test_whatsapp_personal_diagnostics.py`, `test_whatsapp_personal_*.py`. Neither side proves the other, so a frame change needs both.
- Model identity concealment: `test_response_identity.py` owns the redaction rules (alias derivation, token boundaries, any-split streaming equivalence, bounded hold-back, gap/replace). Integration lives at the existing owners: `test_gateway.py` (`record_report` stored/transcript/`done`), `test_openclaw_gateway_stream.py` (split deltas, dropped delta) and `test_openclaw_gateway_rpc.py` + `openclaw_gateway_rpc.test.mjs` (`extraSystemPrompt` staging and forwarding). Tests assert machine-consumed values and `APP_NAME` wiring, never prompt prose.
- `../../.github/workflows/engine-ci.yml` keeps the scoped gate database-free and separately runs `lifecycle-postgres` against PostgreSQL 18.6: setup, setup retry/authorization, start recovery, deletion requests/cleanup/approval, ownership transfers, guest-config transactions, Linkup proxy tokens/revocation, WhatsApp webhook/receipts/reply window/Personal QR, gateway-report relay contention, shared gateway/burst/model-config and native scope locks (`test_openclaw_scope_locks_postgres.py`: shared tenant/owner locks on ordinary claim and settlement, ACL mutators still exclusive). The `whatsapp-bridge` job (Node 26.13.0, `npm ci`, `npm test`, `npm run build`) is separate. Fixture DSNs are `AGENT_SETUP_TEST_DATABASE_URL` (also requires `AGENT_SETUP_TEST_DATABASE_DISPOSABLE=1`), `MARACLAW_TEST_POSTGRES_DSN`, `CHAT_SUBMISSION_TEST_DATABASE_URL` and `BOOTSTRAP_TEST_DATABASE_URL` (start tests reuse the upgrade fixture). Each live fixture isolates and drops its schema. External Redis/connectors/AgentBay/browser/image smoke need their matching integration environment; do not infer live coverage from isolated tests.
