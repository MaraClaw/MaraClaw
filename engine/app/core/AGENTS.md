# app/core

`app/core` contains cross-cutting primitives only: tracing, logging setup, JWT/auth dependencies, permission policy, Redis Pub/Sub lifecycle, and low-level email transport helpers. Canonical closed enum values live in `domain/`; read [`domain/AGENTS.md`](domain/AGENTS.md) before adding or renaming one.

## Trace And Logging

- `TraceIdMiddleware` is pure ASGI (no `BaseHTTPMiddleware`) and handles `http` scopes only: WebSocket and lifespan scopes pass through untouched. It keeps the client's `X-Trace-Id` only when it is 1 to 64 characters of `A-Za-z0-9._-` (anything else gets a new 12-hex id), binds it for the request and unbinds it after, stores `request.state.trace_id`, adds the response header, and logs a targetless arrival line plus one completion line (`<-- METHOD route-template status 0.000s`, or an `ERROR` line with only the exception class). Timing is `time.monotonic()` from arrival to response start. The route is the matched template (`/api/agents/{agent_id}`) or the fixed `unmatched-route`, never the raw path; the same label feeds the latency histogram. Quiet probes (`is_quiet_access_log`: health, live, metrics, unread counts, guest heartbeat) log at debug until they fail.
- `app.main` installs trace middleware first. Preserve that order for request-wide tracing.
- Starlette wraps middleware in reverse order; verify runtime behavior before relying on trace logs for CORS/error paths.
- Use `from app.core.logging import logger`. `intercept_standard_logging()` redirects stdlib logging into the process logger at startup.
- Background jobs that are not inside an HTTP request should call `new_trace_id()` before emitting related logs.
- WebSocket flows set trace ids manually because they do not follow the normal HTTP request lifecycle.

## Metrics

- `metrics.py` owns the in-process instruments and renders Prometheus text exposition 0.0.4. It is a small typed implementation: `prometheus_client` is not in `uv.lock` and no dependency is added. `Histogram` keeps cumulative buckets per label set and is touched only on the event loop thread, so it needs no lock; `observe_http_request(method, route, status, seconds)` (methods outside the standard seven share `OTHER`), `observe_event_loop_lag(seconds)` and `render_metrics()` are the entry points.
- Everything else is read at scrape time from state that already exists: `app.db.pool.pool_stats()` (each pool's own `get_stats()`: max, size, available and waiting gauges plus requests, queued, errors and wait-seconds counters per `pool="main"|"durable"`; the durable pool appears once something opened it) and `LoggingService.dropped_total` (`maraclaw_log_records_dropped_total`, cumulative, a plain read). A scrape takes no pool connection, no Redis call and no lock a request path uses; `tests/test_hot_path.py` fails if that changes.
- Series: `maraclaw_http_request_duration_seconds{method,route,status}` (arrival to response start), `maraclaw_event_loop_lag_seconds` (sampler: `../runtime/AGENTS.md`), `maraclaw_db_pool_*{pool}` and `maraclaw_log_records_dropped_total`. A new label must be bounded (templates, fixed sets), never a path, id or user value.
- `GET /api/metrics` (`app/api/metrics.py`, `build_metrics_router(token)`) exists only while `METRICS_TOKEN` is set: `app.main` mounts it then and otherwise nothing answers (404). It requires `Authorization: Bearer <token>`, compared with `hmac.compare_digest`, else 401 with `WWW-Authenticate: Bearer`. It is `include_in_schema=False`, so `contracts/api-contract.json` and the frontends are untouched, and an empty token raises at build time (it would match an empty credential).

## Security

- `outbound_policy.py` and `outbound_transport.py` enforce public-only destinations for untrusted MCP, webpage reads, and URL polling. Use `public_http_client` to pin each dial to validated DNS answers while retaining TLS hostname verification and disabling environment proxies. MCP clients additionally bind requests to their configured origin. Pooled MCP sessions (`app/services/mcp_client.py`) also get their long-lived client from `public_http_client`; never wrap such a shared client in `async with`, which closes it after one use.
- `security.py` owns JWT creation/decoding, password hashing, and FastAPI auth dependencies.
- Shared loader: `load_user_from_access_token(token, require_active=..., enforce_password_change=...)` loads `UserRecord` **with identity** and optionally enforces `must_change_password`.
- Use from route modules:
  - `get_current_user` - active user; **403** with `{must_change_password: true}` when force-change is pending (all privileged REST).
  - `get_authenticated_user` - allows inactive + force-change; **only** for `GET /auth/me`, `PUT /auth/me/password` and `member_auth.get_member_user` (`/member/auth/me`). Tenant join/transfer routes (`POST /tenants/join`, `/join-suggested`, `/join-default`) depend on `get_current_user`.
  - `get_current_admin` / `require_role(...)` - built on `get_current_user` (inherit force-change gate).
  - `raise_if_password_change_required(user)` - explicit re-check where the actor is reloaded or passed outside the `Depends` chain, e.g. services that re-read `get_with_identity(..., fresh=True)` under locks (`org_departments`, `tenant_email_admin`, `agent_provisioning`, `subscription_boundaries`) and `api/departments.py`.
- Non-Depends JWT auth (file download Bearer header) **must** use `load_user_from_access_token` (not bare `decode_access_token` + `user_dao.get`); file download tickets go through `file_download_tickets.authorize_binding` (`load_user_principal(fresh=True)`). Chat WebSockets redeem single-use tickets and use `load_user_principal(fresh=True)` through `chat_tickets.authorize_message`, which runs the authorization and the session check on one pooled checkout. Bare `get` does not join identity, so `must_change_password` would always look false.
- Use async password helpers from async paths; bcrypt work is intentionally pushed to a thread pool. The executor admits at most `BCRYPT_MAX_PENDING_CHECKS` checks (running plus queued); one beyond that fails at once with 503 and `Retry-After`, hashing parameters and stored hashes untouched.
- `rate_limit.py` is the shared Redis fixed-window limiter (`Limit`, `consume`, `enforce`, shared 429 `too_many_requests`); a Redis error allows the request. `client_address.get_client_ip` is the one client-address helper: it believes `X-Forwarded-For` only from peers in `TRUSTED_PROXIES` (walked from the right), so never read `request.client.host` for a limit or an audit address. Auth policy built on both lives in `services/auth_throttle.py`.
- Token payloads use `sub` for user id, `role` for role and an integer `gen`; `decode_access_token` rejects a missing or non-integer `gen`, and `check_token_generation` (file download and roster export tickets) rejects a stale identity auth generation. Force-change is **not** in the JWT; it is re-read from identity on each request.
- Membership revocation: access tokens also carry `mgen`, the user row's `membership_generation` at mint time (0 for an identity-only subject). `decode_access_token` treats a missing `mgen` as 0 and rejects a present but non-integer, boolean or negative one exactly like `gen`. `check_generations(user_id, identity_id, auth=, membership=)` compares both claims with strict equality against the one `user_dao.get_generations` statement (identity `auth_generation` and `users.membership_generation`, joined on the membership's identity) on every path through `load_user_from_access_token`, including `require_active=False`; neither counter is ever cached in Redis or the session snapshot (a missing field would decode as 0 and match a legacy token), so a stale or missed cache invalidation cannot hide a deactivation or a logout-all. `ChatTicketBinding.membership_generation` carries the claim and `chat_tickets.authorize_principal` runs the same check, for `authorize` on every socket message and for `create` on the principal the route already loaded. Other single-use tickets (file download, roster export) still check only the identity generation.

## Permissions

- `permissions.py` is the shared source of truth for agent visibility, access levels, and relationship access.
- Prefer `list_visible_agents(...)` (DAO). There is no SQLAlchemy visibility query.
- Use `check_agent_access(...)` at HTTP endpoint boundaries. Custom-mode department `use` grants count via `org_department_dao.has_agent_access`. It runs the transfer gate and every read on one `optional_connection_ctx`, and decides creator, administrator, company-level and other-tenant cases from the caller's `user` and the agent alone: no cache read, no fill, no user reload. Only an agent that needs permission rows reads the ACL snapshot, and then it reads the user and, on a miss, the agent again after the observed version, so the version is still observed before every input it guards. A `fresh=True` check re-reads the user from SQL up front unless the caller passes `user_is_current=True` right after `load_user_principal(fresh=True)`.
- `acl_locks.py`: `lock_tenants`, then `lock_user` / `lock_agent`, are `SELECT … FOR UPDATE` inside the caller's `connection_ctx`. Take them before `bump_agent_acl_version`. Order is tenant, subject, agent. `shared=True` uses `FOR SHARE` on tenants and `FOR KEY SHARE` on users for ordinary native claims and settlement. The user mode permits non-key quota updates without a receipt-FK deadlock; ACL mutators' explicit `FOR UPDATE` still excludes both shared modes. Never upgrade these locks within the same transaction.
- Access *decisions* (not agent rows) may be cached in Redis via `access_cache.py`. TTL `AGENT_ACCESS_CACHE_TTL_SECONDS` (0 disables). Policy writes bump `aclver:{agent_id}` **after** the top-level `connection_ctx` commit. `set_cached_level` is skipped if `aclver` changed since compute. Redis errors fail open to DAOs. Do not cache 403/404.
- Auth snapshots (`session_cache.py`, `USER_SESSION_CACHE_TTL_SECONDS`) cache `get_with_identity` **without** `password_hash` or quota counters. A steady-state hit is one Redis round trip: `redis_cache.read_session_keys` sends one non-transactional pipeline of single-key GETs (snapshot, user generation, identity generation) through `guarded`, every key named by the caller and none built server-side (no Lua), so a cluster-aware proxy can route each one. The identity generation key comes from a bounded in-process hint (`session_cache._identity_hints`, user id to identity id, LRU of 10 000, taught by `set_cached_user` and by each hit); with no hint the first read of a membership in a process reads the snapshot and user generation, then the identity generation the snapshot names (two trips, identity after user). A hint is never trusted: a snapshot naming another identity is a miss that corrects the hint. User/identity writes bump `sessver:*` after commit and drop request memo. Sets carry `observed_ver`. Password verify/change/transfer must use `load_identity_for_password` (SQL), never the snapshot hash. Redis **read** errors fall back to SQL; version INCR/DELETE are not skipped by the fail-open circuit.
- Tenant rows may be cached (`tenant_cache.py`). Agent PK reads use request-local `row_memo` only (full agent rows include `api_key_hash` and counters).
- New fail-open caches go through `redis_cache.py` + `get_cache_redis()` (short socket timeout). Tokens, locks, pubsub, and webhooks keep `get_redis()`.
- One breaker guards every fail-open cache read and fill: `await redis_cache.guarded(call)` runs one Redis round trip (`call` is a zero-argument coroutine function doing only the I/O; parse the reply outside) and raises `CacheUnavailableError` instead of waiting when the breaker is open or the call fails. A failure opens it for 2 s; then exactly one caller is admitted as the probe while the rest are refused, a successful probe closes it, a failed one reopens it. A busy pool (`RedisPoolOverloadError`) fails only its call and a cancelled probe hands the slot on. `redis_cache.cache_get/cache_set/cache_set_nx/read_version/read_session_keys`, `access_cache.read_acl_snapshot/read_acl_version/set_cached_level` and `agent_context_cache` already go through it; a new cache read catches `CacheUnavailableError` and falls back to the source of truth. Invalidation writes (`cache_delete`, `bump_version`, `flush_deferred_*`, `_invalidate_now`) never consult or move the breaker. `CacheBreaker(cooldown=, clock=)` takes an injectable clock; tests swap `redis_cache._breaker` and call `reset_circuit()` so one test's outage cannot leave the breaker open for the next.
- `single_flight.SingleFlight` coalesces concurrent misses of one key inside a process: callers share one load task (cancelling a waiter does not cancel it), a failure reaches every waiter and is forgotten so the next call retries. Key it by the observed cache version so a caller after an invalidation never joins an older load, and use it only for loads that do not run on the caller's own transaction (`user_dao.get_with_identity` and `tenant_dao.get` skip it inside a `connection_ctx`).
- Agent tool config mutations that change sandbox egress (`allow_network`, proxy fields) are authorized in `app/api/tools.py` (admin roles), not here; keep permission policy for agent visibility separate from sandbox egress policy.
- Use non-HTTP helpers such as `get_agent_access_level_for_user_id(...)` and `user_can_manage_agent_id(...)` in services/background jobs.
- Keep relationship checks in `permissions.py`. Precedence lives once, in the pure `_decide_agent_relationship` / `_decide_human_relationship`; the single-row `evaluate_agent_relationship_status(...)` / `evaluate_human_relationship_status(...)` (`agent_tool_exec`) and the list forms `evaluate_agent_relationship_statuses(...)` / `evaluate_human_relationship_statuses(...)` (relationship endpoints, gateway send, `_load_relationships_from_db`; results aligned with the input) differ only in how they load. The batch runs a fixed number of statements however many rows it gets (agents, members only for rows without one, users, permission rows, department grants), reads agents and users fresh (never the row memo, preloaded rows or the access cache), neither reads nor fills the access cache, and takes no row locks, so it is safe under the gateway's agent lock. List callers use the batch; never loop the single-row forms or add a memo.

## Events

- Use `publish_event(channel, data)` for Redis Pub/Sub events.
- Three pools, three clients, sized by settings so one process stays under the hosted Valkey connection limit (the sum of `REDIS_MAX_CONNECTIONS`, `REDIS_CACHE_MAX_CONNECTIONS` and `REDIS_PUBSUB_MAX_CONNECTIONS` times the process count): `get_redis()` (durable commands, waits up to `REDIS_COMMAND_WAIT_SECONDS`, below the socket timeout, for a free connection), `get_cache_redis()` (fail-open caches, never waits; connects within `REDIS_CACHE_CONNECT_TIMEOUT`, at most `REDIS_CACHE_SOCKET_TIMEOUT`, so a dead cache host costs one read budget) and `get_pubsub_redis()` (long-lived subscribers only: the realtime subscriber and the gateway report wake, never commands). A pool with no free connection raises `RedisPoolOverloadError`, a `RedisError` that is neither a `ConnectionError` nor a `TimeoutError`: callers that already survive a failed call survive it, but `ping_redis` reports reachable, the cache circuit (`redis_cache`) stays closed and subscribers do not treat it as an outage. Never raise `REDIS_MAX_CONNECTIONS` alone to absorb a burst.
- Do not create ad hoc Redis clients for shared app events. Caches use `get_cache_redis()`; durable paths use `get_redis()`.
- `close_redis()` closes all three pools during app shutdown; event users should not close the process-global clients themselves.

## Existing Exceptions

- Bundled skill-creator payloads under `app/services/skill_creator_files/` may still import `loguru`. Do not "fix" those; they run outside the backend process.
