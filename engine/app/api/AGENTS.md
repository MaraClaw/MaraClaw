# app/api

Flat FastAPI routers. Most export `router` and are mounted from `app/main.py`.

## Registration

- Shared channel LLM helpers live in `app/services/channels/llm_bridge.py`. Import them directly from `app.services.channels.llm_bridge`, not from an API router.
- Default: `prefix=settings.API_PREFIX` so `/agents` → `/api/agents`.
- Routers that set their own prefix and mount without `API_PREFIX`: `triggers.py` and `chat_sessions.py` (`/api/agents`), `clawbook.py` (`/api/clawbook`), `webhooks.py` (`/api/webhooks`), `okr.py` (`/api/okr`), `tavily_proxy.py` (`/api/tavily`). `websocket.py` (`/ws/chat/{agent_id}`) and `pages.public_router` (`/p/{short_id}`) also mount without `API_PREFIX`, but set paths on route decorators rather than `APIRouter`.
- `files.py` exports `router`, `upload_router`, `enterprise_kb_router`. Member file routes (listing, content, download, previews, revisions, restore, locks, workspace upload, skill imports) and `pages.py` publish reach only the root entries in `file_storage_paths.MEMBER_VISIBLE_ROOT_ENTRIES` (the workspace scaffold plus the virtual `enterprise_info`), through `require_member_visible_path` / `visible_storage_key`, on the normalized path and without crossing a symlink in the agent directory (a link the guest plants under `workspace/` must not reach runtime files or another agent). The local backend also refuses any linked path component itself (403), which covers a link swapped in after that check. Uploads refuse a file name that is empty, `.`, `..` or holds NUL (400 `Invalid file name`). The three skill imports write through the storage facade (S3 in S3 mode, never the guest disk directly), take a single-segment folder name (400 `Invalid skill folder name`) and refuse the whole import when a file would land outside `skills/<folder>/` (400 `Skill file path escapes the skill folder`). They write through `skill_install.write_skill_files`: all files or none (a failure partway, cancellation included, undoes the writes and re-raises the original error, so quota answers stay 413/507/503); duplicate paths (compared case-folded) or a file that is also another file's folder are 400; a file or folder in the way, a file changed meanwhile, or a file too large to restore (over 500 KB) that the import would overwrite is 409; a successful import refreshes the agent context for `skills/<folder>`. Anything else at the agent root is guest runtime state (gateway key, `openclaw.json`, gogcli tokens): the root listing omits it and every route answers 404 `Path not found`, admins included. A new member-reachable root entry goes into that set.
- `file_shares.public_router` (`GET`/`HEAD /f/{token}/{filename}`) mounts without `API_PREFIX`, like `pages.public_router`, and without request-wide CRUD binding: the token store is Redis and the body is streamed or redirected. It is public; the token is the credential, and every unusable token answers the same 404. `gateway.py` `POST /file-links` (agent API key) mints the link. Contract: `../../docs/workspace-mirror.md`.
- `metrics.py` exports `build_metrics_router(token)`: `app.main` includes `GET /api/metrics` (fixed path, no `API_PREFIX`, no `bind_crud_connection`: a scrape takes no connection) only while `METRICS_TOKEN` is set, and the route stays out of the OpenAPI schema and the API contracts. Contract: `../core/AGENTS.md` (Metrics).
- `whatsapp.py` is mounted with `API_PREFIX` (same as other IM channels). Webhook paths stay `/api/channel/whatsapp/{agent_id}/webhook`. Guarded tool sends live in `agent_tool_exec/channel_provider_whatsapp.py`, not this router. `background_tasks.py` is a helper, not a router.
- Launch route background work with `schedule_background_task`, not `asyncio.create_task`. It starts the work after the request transaction commits, in a fresh context that carries only the trace id, and drops it on rollback. FastAPI `BackgroundTasks` still run before the request commits.
- `openclaw_updates.py` is mounted with `API_PREFIX` (`/admin/openclaw-updates` platform-admin publish, `/openclaw-updates/{id}`, `/agents/{id}/openclaw-update`). Guest-visible file/upload mutators carry `Depends(guest_write_exclusion)` (409 during an active run); `OpenClawUpdateGateError` maps to 423/409 in `main.py`. Contract: `../../docs/openclaw-updates.md`.
- `departments.py` is mounted with `API_PREFIX` (`/api/departments`, `PUT /api/users/{id}/departments`, and singular `/department`).
- `onboarding.py` exposes only `GET /status`, `POST /start` and `POST /complete`. `POST /onboarding/personal-assistant` is retired: web-e creates the onboarding assistant through `POST /api/agents/` between `start` and `complete`. The `personal_assistant_agent_id` column and `/status` field remain, but nothing in the engine writes the pointer.

## Sessions, triggers, broadcasts

- `chat_sessions.py` is audited (`AUDITED_HTTP_MODULES`). `GET /{id}/sessions/page` (`scope` `mine|all`, `limit` 1..200 default 50, opaque versioned cursor bound to agent + scope) keyset-pages via `chat_session_dao.list_page`; the caller's own canonical conversation (created on demand) leads page one only, outside `limit`. Bad/foreign cursor → 400, never 500. `scope=all` is `org_admin` only (`can_view_all_agent_chat_sessions`, else 403) and returns other owners' conversations with `writable=false`; group and agent sessions keep `writable=true`. `GET /{id}/sessions/{session_id}` is the authorized single lookup (owner or `org_admin`). `POST /{id}/sessions` returns the caller's canonical session. A write to a non-writable session is 409 `session_read_only` (`shared_chat.read_only_refusal`, also sent as the socket error event). A canonical session cannot be deleted: 403 for a non-owner who is not `org_admin`, then 409 `canonical_session_required`. Register `/sessions/page` before `/{session_id}`. The unpaged `GET /sessions` remains for compatibility; `web-e` no longer calls it.
- `triggers.py` `PATCH`: strips `token`/`secret`/underscore keys, writes config only via `agent_trigger_dao.merge_user_config` (SQL merge), never a whole-config update. See `../services/trigger_runtime/AGENTS.md`.
- `webhooks.py` `POST /t/{token}` is public and answers `200 {"ok": true}` for everything it rejects. Order: token shape (exactly 11 or 22 `[A-Za-z0-9_-]`, else return before any body, Redis or SQL) → one `find_webhook_by_token` (unknown → return, no body, no Redis write) → rate limit keyed by the matched trigger (`webhook:rate:{trigger_id}`; hard 60/min plus the agent's `webhook_rate_limit`) → bounded 64 KiB body (413) → HMAC signature → enqueue. Never throttle on `X-Forwarded-For` or the peer address, and never add a per-IP or global unknown-token counter. New tokens are `token_urlsafe(16)` (22 characters); stored 11-character tokens keep working and are never rotated. The partial expression index `ix_agent_triggers_webhook_token` is non-unique and its predicate must match `find_webhook_by_token`'s `WHERE`.
- `notification.py` broadcast: optional `Idempotency-Key` (1..200, blank → 422, same as `schedules.py` manual runs). Replay lookup precedes SMTP and audience reads; the key is claimed (`broadcast_submission_dao.claim`, `ON CONFLICT DO NOTHING`) inside the fan-out `connection_ctx`, so rollback leaves no receipt and concurrent retries serialize on the unique key. Same key, different `title`/`body`/`send_email` → 409 (422 stays validation). `_broadcast_tenant` stays the first gate. Every committed send also inserts one `broadcast_history` row (`broadcast_history_dao.publish`, same transaction, keyed or not, zero recipients included); replay, 409, SMTP refusal and rollback write none. `GET /notifications/broadcast/history` (`limit` 1..100 default 20, opaque `BroadcastHistoryCursor`, bad/foreign-type cursor → 400) keyset-pages `published_at DESC, broadcast_id DESC` for `_broadcast_tenant` only and never returns key or fingerprint.
- `clawbook.py` (audited, self-prefixed) also serves two org-admin read routes, `GET /admin/posts/page` and `GET /admin/posts/{id}/comments/page` (`limit` 1..100 default 30, opaque `cursor`): every post and comment of the caller's tenant, each with `hidden_from_members` (the member feed's `_HIDDEN_AGENT_EXISTS` predicate evaluated in SQL, so the flag means exactly "the member feed omits this"). `org_admin` with a tenant only: members and platform admins get 403 before the cursor or any read. A post of another tenant, without a tenant, or missing is 404. `ClawbookCursor.scope` (`member`|`admin`, default `member`) binds a cursor to its audience, so a cross-scope cursor is 400. Pages: `services/clawbook_pages.py` (`read_admin_*_page`).

## Org departments

- `GET/POST /departments`: `org_admin` is own-tenant; `platform_admin` must pass `tenant_id`. Duplicate name → 409. Create locks in the router and does not bump ACL.
- `PUT /users/{id}/departments`: `org_departments.assign_departments`. `{department_ids: UUID[]}` replaces the full set, normalizes duplicates, and clears on `[]`; returns `{user_id, tenant_id, department_ids}` sorted by UUID. Invalid/foreign departments reject the entire set. End users only. Fresh actor/subject checks follow tenant-first locks; affected old/new agents are locked in UUID order and `aclver` is bumped in the same transaction.
- `PUT /users/{id}/department`: singular compatibility route via `assign_department`; non-null replaces with one membership, null clears all. `GET /departments` returns departments only. Admin `GET /departments/assignments` takes up to 100 repeated `user_id` UUIDs and returns matching membership rows for the resolved tenant.
- Provider organization directory/sync routes are retired. `/api/org/users` and org departments remain; neither requires a provider department hierarchy.
- `agents.py` stores `scope_type=department` at `access_level=use` only, and only for custom scope (other scopes with `department_ids` → 422). Saving private or company deletes every permission row, so those grants disappear. DB check: `ck_department_permission_use`. `GET /{agent_id}/permissions/departments` is managers-only.
- `POST /agents/` accepts optional `department_ids` (default `[]`). Nonempty selections require custom sharing; validate every department against the resolved target tenant before writes. Creator `manage` and deduplicated department `use` grants share the agent creation transaction through `AgentPermissionDAO.create`.
- `GET /agents/default-soul` returns the unrendered scaffold `soul.md` (`{soul}`) so web-e can show and edit it before creation; register it before `/{agent_id}`. `POST /agents/` accepts optional `soul` (max 20000): non-blank text replaces the scaffold soul, then placeholders and `personality`/`boundaries` sections are rendered as usual (`agent_workspace.render_agent_files`).

## Dependencies

- Users: `current_user: UserRecord = Depends(get_current_user)` - not `User`.
- Admin: `get_current_admin` / `require_role(...)` (both inherit `must_change_password` gate from `get_current_user`).
- Agents: `await check_agent_access(current_user, agent_id)`; no discarded DB argument is accepted.
- Persistence: DAOs. Short CRUD routers bind `bind_crud_connection` in `app.main` (one checkout). Routes that call Docker, a CLI or S3 live in a second router of their module mounted without it: `agents.runtime_router` (start, start-new-container, stop, api-key), `advanced.metrics_router` (metrics), `tenants.logo_router`, `pages.publish_router`, and all of `gogcli`. Same paths and models; each DAO call or explicit `connection_ctx()` there is its own short transaction. Do not attach that dependency to websocket / connector inbound / gateway / `tavily_proxy`. Extra `async with connection_ctx():` still joins.
- `agent_setup.py` is self-prefixed `/api/agents/{agent_id}/setup` and mounts without `API_PREFIX` or request-wide CRUD binding. Manage-only `GET` returns safe status; `POST /retry` accepts eligible failed setup with 202, otherwise 409. The service freshly authorizes, owns explicit transactions and rechecks authorization after acquiring the per-agent flock; never move row locks ahead of that flock.
- `admin_search_analytics.py`: platform_admin only. Live SQL over `web_search_events`. Never return raw queries.
- Handlers use canonical arguments without legacy DB placeholders; preserve real `DbConnection` parameters in transaction/locking helpers.
- `websocket.py` redeems single-use `chat_tickets` and freshly loads the bound principal. Only `heartbeat=1` opts in to the `ws-heartbeat` sender (`HEARTBEAT_INTERVAL_SECONDS`, seam `_heartbeat_sleep`): a payload-free `{"type":"heartbeat"}` every 10 s after `connected`, with no DB, Redis or authorization work. It never extends the ticket's auth deadline (4001 still fires); a failed or over-5 s send stops only the sender, which stops in the same `finally` as `ws-presence-refresh`. Input is bounded at the socket: the default `START_COMMAND` in `entrypoint.sh` passes `--ws-max-size` (`Settings.chat_frame_max_bytes`, printed by `python -m app.scripts.chat_frame_limit`), so an oversized frame closes 1009 before parsing; `ChatSubmission.require_within_limits` refuses over-limit `content`/`display_content`/`file_name` (`message_too_long`/`file_name_too_long`, never truncated) before any lock; a socket past `CHAT_SOCKETS_PER_USER` (counted from Redis presence) closes `USER_SOCKET_LIMIT_CLOSE_CODE` 4029 after accept; `SubmissionWindow` (in-process, per socket, injectable `_submission_clock`) answers an over-rate submission with `rate_limited` and keeps the socket open. `files.py` download takes Bearer (`load_user_from_access_token`, identity + force-change) or a single-use `file_download_tickets` ticket from `POST .../files/download-ticket`, freshly re-authorized on redemption; no query JWT. A local-backend download answers `Range` (206/416), `If-None-Match`/`If-Modified-Since` (304) and sends ETag/Last-Modified (`file_stream.file_response`); a ticket is spent by its first request, so a resumed or seeking download needs a new ticket or the Bearer header. S3 downloads redirect to a presigned URL. `gateway.py` uses agent API keys.
- `gogcli.py` is mounted (`/api/agents/{id}/gogcli`); users are `UserRecord`.

## Organization plans and admissions

- `organization_admissions.py` (audited, bound CRUD connection) mounts with `API_PREFIX`: public `GET /organization-plans` (catalog in `services/organization_plans.py`) and `POST /organization-admissions/quote` `{organization_name, email, phone, tier, billing}` (`OrganizationAdmissionQuoteRequest`: name trimmed 1..200, control characters rejected; `phone` is the shared `PhoneNumber`, normalized to E.164, `billing` is `monthly|annual`; missing or invalid → 422) → 200 `OrganizationAdmissionQuote` (server price, VND amount, bank recipient, `MO` reference, seven-day `expires_at`, HMAC `quote_token`; nothing is stored) or 409 `{code, message}` (`payments_not_configured`, `admission_already_pending`, `email_registered`, `domain_claimed`). The paid submit is `organization_admission_evidence.py` (same prefix, unbound because of the upload and the bounded storage read, deliberately **not** in `AUDITED_HTTP_MODULES` for the capacity-evidence reason below, so `OrganizationAdmissionAcknowledgment` is registered explicitly in `scripts/api_contract_registry.py`): `POST /organization-admissions` multipart `quote_token` + `file` → 202 `{status: pending, reference}` (400 `quote_invalid`, 410 `quote_expired`, 413/415, 429 `too_many_requests` per client IP, 409 `quote_already_used`), and genesis-only `GET /admin/organization-admissions/{id}/evidence` (sandboxed download). `GET`/`POST .../decision` and `POST .../{id}/retry-email` under `/admin/organization-admissions` are genesis platform admin only (`services/organization_admissions.require_genesis_platform_admin`: fresh persisted role + `is_genesis` + identity). Approving a named request provisions in one transaction through `tenant_provisioning.create_tenant_with_org_admin` (tenant named after the request with the request's tier and phone, genesis `org_admin` with a generated one-time password, `must_change_password`, default domain claim) plus a durable credential email intent (`organization_admission_credential_emails`, AES-GCM sealed payload bound to the request id). Existing identity → 409 `Admin email is already registered`, claimed domain → 409 `Email domain is already claimed`, legacy request without a name → 409; all roll back and leave the request pending. Replay returns the original decision and never provisions or rotates again. `services/organization_admission_email_worker.py` (worker role) sends it after commit over the platform (MaraClaw) SMTP only, deletes the payload once SMTP accepts, retries transient/unconfigured failures with bounded backoff, and settles a changed password or deactivated account as terminal `failed` without sending. Items expose `organization_name`, `phone`, the paid quote snapshot (`billing`, `amount_usd`, `usd_vnd_rate`, `amount_vnd`, `recipient`, `payment_reference`, `evidence` metadata; never the storage key), `credential_email_status` (`pending|sent|failed|null`) and `credential_email_error` (static code); `retry-email` re-queues the same intent, never credentials. Distinct from `company_admissions.py` (member join, org genesis reviewer).

## Capacity orders

- `capacity.py` (audited, mounted with `API_PREFIX`, **not** bound to `bind_crud_connection`) serves `/api/capacity/*`: org admins of a non-system company order, cancel and read; platform admins read any company with `?tenant_id=`. `capacity_evidence.py` (same prefix, unbound because of the upload and the bounded storage read, deliberately **not** in `AUDITED_HTTP_MODULES`: the multipart body schema FastAPI derives has no public name the Zod generator accepts) serves `POST`/`GET /api/capacity/orders/{id}/evidence`: pay (multipart `file`, PNG/JPEG/WebP/PDF by magic bytes, at most 10 MiB, 415/413 otherwise) and the sandboxed download. `admin_capacity.py` (audited, bound CRUD connection) serves `/api/admin/capacity-orders*` (any active platform admin reviews) and `/api/admin/capacity-payment-settings` (genesis platform admin only). Both routers stay thin: authorization, locking and state live in `services/capacity_orders.py`. The two list routes (`GET /api/capacity/orders`, `GET /api/admin/capacity-orders`) take `limit`/`offset` plus an optional `cursor`; `CapacityOrderPage.next_cursor` is set only when `has_more`. The opaque, versioned, view-bound cursor lives in `services/capacity_order_cursor.py` and is decoded only after authorization, so a malformed or foreign one is 400 and never masks a 403. Conflicts are `409` with `detail {code, message}` (`services/coded_errors.conflict`, shared with the organization admission flow). Request ints are strict. Schemas: `schemas/capacity.py`; never expose the evidence storage key. `enterprise.py` answers 404 for the reserved `RESERVED_SETTING_KEYS` on the generic system-settings endpoints. Contract: `../../docs/admin-apis.md` (A4, B12), `../../docs/organization-pricing.md`.

## Auth / admin genesis

- Registration uses `POST /auth/register/init`; OAuth registration/login uses `POST /auth/{provider}/callback`. Fresh-only installs do not expose `/auth/register`, `/auth/register/sso`, or `/auth/email-hint`. Auth responses use `needs_org_confirm`, not `needs_company_setup`.
- SSO state: `GET /auth/{provider}/authorize` (anonymous) mints the state through `services/oauth_state.py` (Redis `GETDEL`, 600 s, stores provider + redirect URI + `sign_in|bind` intent). `oauth_callback_flow` (code step) and `bind_identity_flow` consume it before any provider call and exchange with the stored redirect URI; the pending tenant-selection token is `GETDEL`-redeemed and bound to provider + audience. Redis failure is 503, never a fallback. PKCE, redirect allowlists, rate limits and the scan-session flow are separate.
- `auth.py`: password login returns `must_change_password` on `TokenResponse` / `AuthUser` / `IdentityOut`. Open registration hard-codes `is_platform_admin=False` (never first-user elevation). Reset/verify emails resolve the frontend via `frontend_origin` (allowlisted Origin/Referer).
- Throttling (`services/auth_throttle.py`, Redis, fails open): `login_flow` (shared and member login), `forgot-password` and `resend-verification` check one budget per client address and one per account digest before any lookup, password check or email send; member `register/init`, `verify-email` and `/{provider}/callback` check the address budget; `chat-ticket` and `download-ticket` check the address (route dependency) and then the signed-in user, ahead of the chat user load, the agent access check and the ticket write. Every refusal is the same 429 with `Retry-After`, so known and unknown accounts look alike. Webhooks stay free of per-IP counters.
- `PUT /auth/me/password` uses `get_authenticated_user`; rejects `new_password == old_password`; clears `must_change_password`. Password reset also clears the flag.
- `admin.py`: `POST /companies` requires `name`, `tier` (`OrganizationPlanId`, no default: missing or unknown → 422), `phone` (`PhoneNumber`: international, normalized to E.164, missing or invalid → 422), `admin_email`, `admin_password` (optional display name). Creates tenant + genesis `org_admin` with `must_change_password=True` and the tier and phone stored on the tenant, in one transaction via `tenant_provisioning.create_tenant_with_org_admin`; the audit `changes` carry `tier` and `phone`, and `CompanyStats.tier` / `CompanyStats.phone` are `tenants.tier` / `tenants.phone`. Unique email race → 409. `POST /platform-admins` is **genesis platform admin only**. Genesis PA may `PATCH /platform-admins/{id}/active`. Admin trail: `GET /audit-logs`. `GET`/`PUT /companies/{id}/agent-sections` (platform admin) read/replace the agent page sections hidden for a company (`im_config["hidden_agent_sections"]`, ids in `core/domain/agent_sections.py`, 422 on unknown id or all hidden, audit `company_agent_sections_update`); members read it as `TenantOut.hidden_agent_sections`.
- `tenants.py`: `POST /` is platform-admin only and creates a tenant with its genesis org admin and required `tier` and `phone` (same service and 422 rules as `POST /admin/companies`; `TenantOut` carries no phone). Join always assigns `member`. Assign-user cannot set `org_admin`.
- `users.py`: `POST /org-admins` and promoting to `org_admin` are **genesis org admin only**. Promoting to `platform_admin` is **genesis platform admin only**. Genesis OA may `PATCH /org-admins/{id}/active`. PA/OA may `PATCH /{id}/active` for end users (also stops that user's agents/triggers/schedules). User detail includes `agents_count` and each agent's `daily_messages` (null without a tier cap); `POST /{id}/agents/{agent_id}/daily-messages/reset` zeroes today's count with the detail page's scope (404 unknown/foreign agent, 409 no cap) and audits `agent_daily_messages_reset`. Company trail: `GET /admin-audit-logs`.
- Inventory for clients: `docs/admin-apis.md`.

## Catalog / secrets

- `tools.py`: tenant override is platform-admin only; catalog mutations need org/platform admin; mask company/agent secrets; `/test-mcp` uses the shared async public-destination policy, with connection-time enforcement in `MCPClient`.
- Tool ownership policy: `services/tool_ownership.py`, using `UserRecord.is_platform_admin` (role or identity). PA may mutate any catalog record. OA record writes require non-builtin source plus non-null record and caller tenant IDs that match; shared/foreign rows and tenantless OA are denied. Builtin source stays shared even if tenant-tagged. Other roles cannot mutate.
- Builtin config-only PUT may replace `tenant_settings` config for a concrete authorized PA/OA target (OA own tenant only). Non-builtin config is a row write requiring record rights. Config is a full replacement, never a merge. Metadata or mixed config + metadata requires record rights before any settings/DAO write; reject the whole forbidden request. Bulk preloads and authorizes all existing rows before any write, silently skipping missing IDs. Delete keeps `type=builtin` 400 and denies unowned rows before deleting assignments. Keep `get_current_user` force-password gating.
- Only catalog GET adds required `tenant_id: str | None` (stored owner) and `capabilities: {can_edit_details: bool, can_delete: bool, can_configure: bool}`. Details follows record rights; delete additionally excludes builtin type; config requires record rights for non-builtin source or a concrete authorized target for builtin source. Populate using the same policy and resolved target; member reads have all false. Existing keys and agent-installed/config response shapes stay unchanged. Exact matrix: `docs/admin-apis.md` B7.
- `update_agent_tool_config`: only `platform_admin` / `org_admin` may set `allow_network` or proxy fields.
- LLM pool writes (`/enterprise/llm-models`, `/llm-test`, `/llm-providers`) are org/platform admin only. Members may `GET /llm-models` for the enabled catalog (no keys or base URLs). Helpers: `app.services.enterprise_llm`. End users and agents may use **only** their company's pool rows (`model_usable_in_tenant` rejects global and cross-tenant). Grok SuperGrok / X Premium device-code is `POST .../grok-subscription/start` + `GET .../grok-subscription/status`. ChatGPT Plus / Pro / Team browser PKCE is `POST .../chatgpt-subscription/start` → `{attempt_id, authorization_url, expires_in}` (503 while `CHATGPT_OAUTH_REDIRECT_URI` is empty) and owner-bound, read-only `GET .../status?attempt_id=...` → `{status, attempt_id, model_id?, detail?, expires_in?}` (no provider call), which the console polls. Keep enterprise unbound from request-wide CRUD transactions so the browser exchange never holds a DB checkout.

## Agent deletion and ownership

- `DELETE /agents/{id}` is `platform_admin` only; everyone else (even the creator or an org admin) gets 403 `agent_deletion_requires_request`.
- `agent_deletion_requests.py` (`/api/agent-deletion-requests`): `POST` `{agent_id, reason}` (owner or org admin with manage; reason trimmed, 1..1000), `GET` list (`status`, `agent_id`, `limit`, `cursor` → `{items, next_cursor}`; members see their own, eligible org admins the company), `GET /{id}` (records an eligible org admin's view), `POST /{id}/approve` (idempotent; needs a prior view), `POST /{id}/cancel` (requester withdraw). Two distinct fresh-eligible org admins, or the active genesis org admin, execute through `snapshot_agent_teardown` + `agent_dao.delete_with_related` + `schedule_agent_teardown`. Stale owner/tenant/agent cancels the request (`cancel_reason`). Lock order: tenant → sorted users → agent → request.
- `POST /agent-ownership-transfers` `{from_user_id, to_user_id, agent_ids}`: active same-company org admin; source `member`/`agent_admin` (active or not), target active `member`/`agent_admin`; atomic, quota-checked, cancels pending deletion requests (`owner_changed`). `POST /agents/{id}/handover` reuses the same service (`services/agent_ownership_transfer.py`).
