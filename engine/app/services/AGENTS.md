# app/services

This is the main business layer. It is intentionally mixed: flat service modules plus specialized runtime subpackages.

## Boundaries

- Keep route handlers thin. Reusable domain behavior belongs in services.
- New storage behavior goes under `storage_runtime/`.
- New sandbox backends go under `sandbox/local`, `sandbox/api`, or `sandbox/remote` and are registered through `sandbox/registry.py`. Read `sandbox/AGENTS.md` and `sandbox/local/AGENTS.md` before changing isolation, proxy, or bwrap behavior.
- New trigger behavior goes under `trigger_runtime/`, not in `trigger_daemon.py` unless it is process-loop wiring.
- New LLM provider/protocol work goes under `llm/`, in `base.py`, `types.py`, `registry.py`, `factory.py`, or `providers/`. The `llm/client.py` facade is retired; import from the owning module. Company pool RBAC (who may add keys / assign tenant models) lives in `enterprise_llm.py`; routes stay thin. SuperGrok / X Premium device-code is `grok_oauth.py` (fakeable HTTP) + `grok_subscription.py` (session + encrypted pool upsert + refresh). ChatGPT Plus / Pro / Team uses browser OAuth PKCE and a pasted callback URL: `chatgpt_pkce.py` validates locally, `chatgpt_subscription_store.py` owns encrypted-verifier Redis tickets (600s, GETDEL claim, owner-bound 300s results), `chatgpt_subscription_handoff.py` owns short transaction/network boundaries, `chatgpt_oauth.py` exchanges/refreshes tokens, and `chatgpt_subscription.py` persists encrypted credentials and activates pool rows. No ChatGPT device fallback or process-local pending state. Engine inference builds clients with `create_fresh_llm_client_from_model` (refreshes a stale subscription token, then Codex Responses for ChatGPT), not `/chat/completions`; the direct `create_llm_client_from_model` constructor never refreshes. Details: `llm/AGENTS.md`.
- Per-account agent caps: `quota_guard.agent_limit` / `agent_capacity` are the only policy (tier cap, `OrganizationAgentLimit` via the plan catalog, from an approved `organization_admission_requests.provisioned_tenant_id` link, else the stored user quota). Creation (`agent_provisioning`), expired-agent renewal (`check_agent_renewal_quota`), ownership transfer and paid company transfer reuse it under the shared tenant/user locks; renewal counts against the owner, not the acting admin. Do not add route-level policy checks. See `../../docs/organization-pricing.md`.
- New document conversion belongs in `document_conversion/`, not in `agent_tools.py`.
- Inbound office-document parsing belongs in `document_parser/` (local `anydoc` / `firecrawl-anydoc`). Do not add format-specific extractors in `files.py` or `agent_tool_exec/document_reading.py`. `text_extractor.py` is gone — do not recreate it. Ordinary text decoding stays local. Do not route CSV/HTML/Markdown generation through anydoc.
- New OKR behavior should use focused `okr_*.py` modules. Dashboard period math is `okr_periods.py` (UTC). HTTP models are `app/schemas/okr.py`. Do not grow `okr_reporting.py`. Gap/outreach still lives in `app/api/okr.py`.
- Provider organization department/people sync and its adapter/coordinator package are retired. Shared `org_members` identity/contact/profile data and agent relationships remain; do not recreate the sync subsystem.
- Org departments belong in `org_departments.py` (multiple departments per end user). Set replacement validates every department before writing, locks via `acl_locks`, and transactionally bumps agent ACL versions for the union of old/new `scope_type=department` grants. Singular assignment delegates to replace-with-one or clear.
- New tool execution handlers belong in `agent_tool_exec/` (`@register`). Seed rows go in `tool_definitions/` (composer `builtin.py`). OpenAI catalog shapes go in `agent_tools_definitions/` (package). Runtime visibility/config in `tool_runtime/`. Keep `agent_tools.py` and `tool_seeder.py` as compatibility/orchestration surfaces. Page-read lives in `agent_tool_exec/web_read.py` (`read_webpage`). Web search/fetch are guest image-bundled Tavily skills; `tavily_runtime.py` supplies config keys and engine HTTP is `tavily/` key-ring/proxy — not a function-calling tool.

- `tool_config.py` owns tenant-scoped tool settings (`tenant_settings`) and sensitive-field encryption/decryption/masking helpers. Distinct from `tool_runtime/tool_config.py`, which loads, merges, and caches per-agent runtime config.

## God Files

- `agent_tools.py` is the primary no-more-growth file. Avoid adding unrelated tool families, conversion helpers, dispatch branches, or catalog tables there. Leftover names are `@register`ed in `agent_tool_exec/_agent_tool_exec_leftover.py`; Normal `dispatcher.execute_tool` uses the registry, with MCP execution for unregistered names, not duplicate builtin branches; the post-approval `_execute_tool_direct` is a separate fixed builtin allowlist (`agent_tool_exec/AGENTS.md`).
- Keep provider logic in the focused LLM modules, not a recreated `llm/client.py` facade. `tool_seeder.py`, `agentbay_client.py`, `agent_seeder.py`, `feishu_service.py`, `okr_reporting.py`, and `auth_provider.py` are also large enough to prefer adjacent focused modules for new work.
- Other flat hotspots include `skill_seeder.py`, `resource_discovery.py`, `heartbeat.py`, `agent_context.py`, `workspace_collaboration.py`, `email_service.py`, `template_seeder.py`, `channel_user_service.py`, `sso_service.py`, `dingtalk_stream.py`, and `okr_scheduler.py`; extend them only when the change belongs to that exact domain.
- `chat_persist.py` wraps post-LLM message/session/`last_active_at` writes in one `connection_ctx`. `agent_context_cache.py` is the short-TTL Redis cache for soul/memory/skills; invalidate on those workspace writes only. Sets carry `observed_ver` so a stale fill cannot win after invalidate.
- `im_token_cache.py` shares Feishu/WeCom/DingTalk bearer tokens across workers. Keys hash public id **and** secret. DingTalk OAuth2 vs oapi use different provider prefixes. Misses go through `get_or_mint_im_token` (one task-owned mint per key per event loop; failures reach only current waiters and are never cached). Rotation drops are unconditional; provider-rejection drops use `drop_rejected_im_token` (compare-and-delete). `channels/dedup.py` (process-local plus fail-open Redis hints) is never authoritative; native-event acceptance and replay are decided by the durable `channels/submissions.py` receipts.
- `agent_runtime/` is removed. Do not recreate it, add `AGENTS.md`, or treat it as live. Same for deleted `group_*` / `heartbeat_runtime` bytecode.

## Guest Lifecycle

Operator policy and limitations: [guest containers](../../docs/guest-containers.md).

- Keep orchestration in `agent_lifecycle.py`; identity, admission, ports, the guest image rule, readiness and observed diagnostics belong in `guest_identity.py`, `guest_admission.py`, `guest_ports.py`, `guest_image.py` (the local-only image rule and the image check before admission), `guest_readiness.py` (bounded readiness and early exit on Docker state) and `guest_container_status.py`, not new branches in `agent_manager.py`.
- Canonical names use the full agent UUID. Stop/remove only inspected container IDs with an exact `maraclaw.agent_id` ownership label; legacy short names are eligible only with that label. A conflicting recorded/canonical reference must fail before destructive work.
- Ordinary `start_container` delegates to `guest_start.py`: reuse a single owned running guest unchanged, resume an owned stopped guest in place, create only when absent, and require bounded application readiness before publishing `running`. Explicit replacement is separate (`rehydrate=False` for upgrades). Rehearse replacement config/native-file generation before admission and ownership checks; stop old owned writers before materializing storage or applying filesystem/config/auth writes. Those writes are not transactional. Do not promise atomic replacement or rollback.
- `agent_start_store.py` commits start intent before Docker work and conditionally publishes runtime against operation/owner/tenant/expected-container and fresh eligibility. Required worker loop `agent_start_reconciler.py` replays pending starts and cleans cancelled candidates; it must not restart arbitrary agents or defeat stop/disable/expiry/transfer/delete. Failed starts retain recoverable intent; failed stop commits `stopped` under the flock before 502. Preserve the explicit no-Docker `idle` compatibility path.
- Lock order is per-agent flock, then optional shared agents-root `_guest_admission` flock through admission and creation. Aggregate admission coordinates only cooperating engine starts on one host with the shared filesystem; it does not cover Docker restarts, manual Docker or multiple hosts.
- Per-guest limits apply only on new/replacement creation, never automatic live updates. Port allocation prefers the persisted in-range port and permits at most eight total attempts, retrying only recognized bind conflicts.
- `agent_stops.py` must read fresh stopped state under the per-agent lock and use compare-and-set for missing references. Preserve `agent_orphans.py` label/network/age checks and fresh locked ownership/upgrade guards for existing-agent duplicates. Neither path is a worker auto-restart feature. The stopped-container worker (`agent_stops.reconcile_stopped_containers`) runs as the heartbeat loop's single-flight child task alongside ticks, never awaited by one and never beating.
- Setup recovery (`agent_setup.py`, `GET /api/agents/{id}/setup`, `POST .../retry`) is manage-only with fresh principal/tenant checks and post-flock reauthorization. Keep its router free of request-wide CRUD binding. Retry accepts eligible failed work only, never steals running claims; successful replay clears durable credentials/files and returns `idle`.
- Deletion snapshots frozen task history and paths into `agent_deletion_cleanup` transactionally with row deletion. No FKs intentionally; cleanup survives agent/user/tenant removal. Post-commit callbacks accelerate, while the stopped-container worker durably retries. `agent_deletion_cleanup.py` removes owned writers before `agent_deletion_archive.py` publishes one resumable archive; Docker/ownership/archive failures retain workspace and pending intent. Baseline DDL is fresh-only, not an upgrade patch.
- Diagnostics are additive, safe observations of Docker health/OOM/limits/ownership/port drift, not readiness guarantees or automatic repair.

## Startup And Seeders

- Seeders are startup-path code and must be idempotent. `app.runtime.lifecycle.lifespan` can invoke `app.runtime.bootstrap.bootstrap` repeatedly when bootstrap is enabled; see `../runtime/AGENTS.md` for ownership.
- Keep optional seed/bootstrap failures scoped and logged; do not make optional seeders bring down unrelated roles unless the caller explicitly requires that.
- **Required system orgs:** `system_org_seeder.ensure_system_orgs()` seeds MaraClaw and KABERs in one transaction on fresh databases; no existing-organization migration is provided. A missing KABERs genesis org admin requires `KABERS_ORG_ADMIN_EMAIL` / `KABERS_ORG_ADMIN_PASSWORD`; an existing genesis is unchanged. New genesis must change password on first login, and bootstrap does not claim its email domain. All system-org seed failures propagate.
- **Exception - genesis platform admin:** `platform_admin_seeder.ensure_platform_admin()` is **required** on bootstrap. It first requires usable genesis credentials in the database; only then falls back to `PLATFORM_ADMIN_EMAIL` / `PLATFORM_ADMIN_PASSWORD`. Raises `PlatformAdminSeedError` when neither source is present. `app.runtime.bootstrap` propagates every PA seed failure (fail-closed). Do not demote this to warn-only.
- Platform admin rules: create path sets `must_change_password=True`; existing identity only elevates if env password verifies (never elevate by email alone; never re-enable a disabled identity; never overwrite password when genesis credentials already exist); genesis membership is the **MaraClaw** system org.
- Agent seeders (`agent_seeder`) look up `first_by_role("platform_admin")` and run **after** platform admin seed.
- New companies: `tenant_provisioning.create_tenant_with_org_admin` (slug + identity + `org_admin` + participant + `bind_org_member`). Used by `POST /api/tenants/` and `POST /api/admin/companies`. Duplicate admin email → `AdminEmailTakenError`. The genesis admin email host is claimed as the tenant's default email domain (`techadmin@marathon.vn` → `marathon.vn`). Domain already claimed → `DomainClaimedError`.
- Disable/enable a company: `tenant_lifecycle.set_tenant_active`. MaraClaw/KABERs (`is_system` / `is_default_end_user_org`) cannot be disabled. Disable deactivates members (not `platform_admin`), stops agents, and turns off triggers/schedules. Enable restores members only (agents/automations stay stopped).
- Reset/verify email links: `frontend_origin.resolve_frontend_base_url`.
- Additional admins: `admin_provisioning.py`. Genesis is `users.is_genesis`. Only those callers may create another of the same role, or activate/deactivate the other admins of that role.
- Admin trail: `admin_audit.py` → `admin_audit_logs` (actor, action, time, `changes` before/after). Distinct from agent-scoped `audit_logs`. Never raise on write failure.
- New default tools/templates/agents should preserve tenant/global visibility assumptions already encoded in the current seeders.

## Connectors

- Long-running connector runtimes use manager singletons such as `feishu_ws_manager`, `dingtalk_stream_manager`, `wecom_stream_manager`, `wechat_poll_manager`, and `discord_gateway_manager`.
- Connector managers start only under the `connector` role, from lifespan `start_all` **after** `init_pool`. Do not start process-wide loops from ordinary request handlers (one `start_client` after config save is the existing exception).
- Preserve provider-specific identity semantics such as Feishu `user_id` vs `open_id`, WeCom `external_id` vs `unionid`, and SSO secret differences.
- Slack and Teams are webhook/API integrations, not lifespan daemon managers.
- Personal WhatsApp (QR) is not a manager singleton: the `connector` role runs `channels/whatsapp_personal_supervisor.py` (Node bridge in `connectors/whatsapp`). The required worker loop `openclaw_dispatch_reconciler.py` recovers pending native lane heads, including due Personal bursts, in keyset pages of 50 with a one-second scan interval; it never replays delivered work. Exact guest evidence can settle an unconsumed interruption (`openclaw_interrupted_inputs.py`) or adopt an already published successful recovery receipt (`openclaw_recovered_inputs.py`, `openclaw_recovered_dispatch.py`). Contract: `channels/AGENTS.md` and `../../docs/shared-openclaw-runtime.md`.
- Auth providers, SSO, Google OAuth and IM channels remain supported independently of retired provider directory sync. Do not remove login, identity binding or channel behavior when changing shared organization members.
- Native dispatch schedules one owned task per conversation lane, bounded by `OPENCLAW_AGENT_MAX_PARALLEL_TURNS`; Shared stays FIFO. `openclaw_gateway_stream.py` owns bounded best-effort web deltas, `openclaw_gateway_delivery.py` owns terminal persistence/publication, `response_identity.py` owns the identity prompt and configured-model-id redaction applied at both, and `gateway_report_wake.py` accelerates the durable relay after commit. Wire correlation is `turn_id`, distinct from the assistant `message_id`. See `../../docs/shared-openclaw-runtime.md` and `../../docs/gateway-report-delivery.md` before changing these boundaries.
