# app/services/gogcli_skill_files

This directory is not a normal backend service package. It is the bundled gogcli skill catalog served to opted-in OpenClaw agents.

## File Convention

- Each subdirectory contains one `SKILL.md` payload for a gogcli-integrated tool such as `gog-docs`, `gog-sheets`, `gog-drive-audit`, `crabbox`, or `gog`.
- Subdirectory names are canonical skill folder names returned by `gogcli_runtime.gogcli_skill_folder_names()` when `GOGCLI_ENABLED` is active.
- `seed_gogcli_skill()` reads each `SKILL.md`, parses frontmatter `name` and `description`, and seeds a non-default builtin `Skill` row plus file content.
- Many payloads are generated by upstream `scripts/gen-agent-skills.mjs`; preserve generated comments, command examples, and relative references like `../gog/SKILL.md`.

## Editing Rules

- Do not rename subdirectories or `SKILL.md` files without updating the gogcli packaging and serving path.
- Do not rewrite bundled skill text for backend style cleanup. These files are agent-facing instructions, not Python modules.
- Keep secrets, live OAuth state, keyring passwords, and local gogcli data out of this tree.
- If adding a new tool folder, include exactly one `SKILL.md` with valid frontmatter and update tests that assert the vendored skill inventory.

## Tests

- `tests/test_gogcli_runtime.py` asserts the vendored folder inventory.
- Gogcli API, persistence, and agent-manager behavior are covered in focused `tests/test_*gogcli*.py` files; avoid live Google credentials in tests.
