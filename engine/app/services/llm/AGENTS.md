# app/services/llm

This package owns provider protocol handling and agent-facing LLM orchestration.

## Layers

- `base.py` defines the abstract `LLMClient`, callback types, and `LLMError`.
- `types.py` defines shared message/response/stream/tool-call shapes and provider-format conversion helpers.
- `registry.py` owns `ProviderSpec`, aliases, provider manifests, protocol/client mappings, base URLs, and token-limit helpers.
- `factory.py` owns `create_llm_client(...)`, `chat_complete(...)`, and `chat_stream(...)`. Identical configs reuse a cached wrapper (`client_cache.py`, key hashes secrets). HTTP is pooled by timeout in `http_pool.py`; wrapper `close()` detaches and does not tear down the pool.
- `providers/` contains provider/protocol clients. Read `providers/AGENTS.md` before changing protocol parsing or streaming normalization.
- `client.py` has been retired. Import types, clients, registry helpers, and factory functions from their owning modules; do not recreate a compatibility facade.
- `caller.py` is the agent orchestration layer. Agent/chat/trigger/websocket flows should enter through `call_agent_llm`, `call_agent_llm_with_tools`, `call_llm`, or `call_llm_with_failover`.
- `call_agent_llm(agent_id, user_text, ...)` and `call_agent_llm_with_tools(agent_id, system_prompt, user_prompt, ...)` own their DAO reads. Do not pass DB placeholders or a `db` keyword.
- `router.py` picks the model for a conversational turn. An agent has exactly two model slots, primary and fallback: `select_turn_model` runs the primary (the fallback only when the primary is unusable, or while the primary's provider circuit is open and the fallback's is not: slot `fallback`, reason `primary_unhealthy`, no failover target) and names the fallback as the failover target, then passes the **selected** model into `call_llm_with_failover`. `call_agent_llm_with_tools` (background loops), the heartbeat and one-shot loops and the supervision-reminder reply route through the same function. Do not grow this logic inside `caller.py`.
- OpenClaw Docker guests do not call the engine LLM and support only `agents.defaults.model` primary plus fallbacks. `app.services.openclaw_routing` selects the slot at enqueue, persists `selected_slot` / `guest_model_ref` on `gateway_messages`, and each claim rewrites the bind-mounted `openclaw.json` from that stored selection. A stored ref that no assigned model matches keeps the row pending (never a substitute). Guest failover uses the tenant fallback slot. Guest routing goes through `select_turn_model` too, so it follows the circuit state the engine's own calls observed; guest calls never report health.
- `turn.py` is the preloaded `TurnContext` / `ModelBundle` (agent/models/user) so callers skip redundant DAO loads. Do not hold a DB connection across `call_llm*`.
- `utils.py` handles strict encrypted API-key decryption (invalid ciphertext is rejected; no plaintext fallback), chat-history conversion, and truncation that preserves assistant/tool-result pairs.
- `reasoning.py` maps canonical `none|low|medium|high|xhigh|max|ultra` onto provider-native request fields. Do not encode those translations in individual provider clients.
- `vision_content.py` builds vision/screenshot parts when the selected model supports vision.
- `finish.py` defines the required `finish(content=...)` control tool.
- `failover.py` classifies retryable provider failures. An `LLMHTTPError`'s status code decides first: 429 and 5xx are retryable and every other status is not, whatever its body says (a 400 whose body mentions a timeout is never retryable). An error without a status keeps its message-based classification, except that a typed `httpx.TimeoutException`/`TimeoutError` whose message names nothing is retryable. `caller.is_retryable_error` classifies the `[LLM Error] ...` reply string, which has lost the status, so it stays message-based.
- `provider_health.py` is the in-process circuit per provider connection (one `LLMModelRecord` row, so a tenant's exhausted key or one overloaded model cannot shut out other rows). `LLM_PROVIDER_FAILURE_THRESHOLD` (5) consecutive retryable failures open it; while open every call is refused with `ProviderUnavailableError` (an `LLMError` whose `unavailable` text `classify_error` reads as retryable, so `call_llm_with_failover` still falls back) and `select_turn_model` routes new turns to the fallback. After `LLM_PROVIDER_COOLDOWN_SECONDS` (30) exactly one caller is admitted as the probe: its success closes the circuit, its failure reopens it, and everyone else is still refused; a probe that proves nothing (cancelled, lease lost, a bug) hands the slot to the next caller. A 4xx other than 429 is an answer from a live provider: it never counts toward opening and resets the streak. State is per process, never in Redis, and the clock is injectable (`ProviderHealth(clock=)`). `call_llm` and `BackgroundToolLoop.try_model` call `ensure_available(model)` before charging the daily call (a refused call is free) and wrap the one provider request in `guarded(model, call)`, which reports the outcome. A model without a UUID row id is not tracked. The other engine-side callers go through the same gate. The heartbeat and one-shot loops (`heartbeat.py`) and the supervision-reminder reply pick their model with `load_agent_model_bundle` + `select_turn_model` (no failover target: a failed request is not retried on the fallback), skip the run when that model is still refused (one warning; a heartbeat skips before it drains the agent's inbox, a one-shot also notifies its requester), check `ensure_available` before every round's `consume_agent_llm_call` (a reminder reply is one request with no charge) and wrap each request in `guarded`. The OKR company report (`okr_reporting._generate_llm_report_content`) wraps each primary/fallback `chat_complete` in `guarded`: a refused model is skipped without a request, and when every configured model is refused it logs one warning and returns the deterministic content instead of raising, while a model that was asked and failed still raises so the prior report is kept. The one direct provider call left outside the gate is the admin key test in `api/enterprise.py`: it probes explicit, possibly unsaved credentials on demand and must reach the provider while a circuit is open. Waiting stays in `retry_policy.py`; the tracker never sleeps or retries.
- `retry_policy.py` is the one retry policy for provider HTTP, called from inside each provider module for `complete` and `stream`: 3 attempts, jittered exponential backoff (1 s base, 8 s cap), `Retry-After` seconds or HTTP-date is the floor of the wait (jitter adds up to the 1 s base delay on top, so callers told the same wait do not return together) and the wait never passes 30 s, an injectable sleep and random draw (`RETRY_POLICY`). It retries `httpx.ConnectError`/`ReadError`/`ConnectTimeout` and HTTP 429/500/502/503/504/529; other 4xx raise on the first attempt. A stream retries only until its first `on_chunk`/`on_tool_delta`/`on_thinking` fires (`StreamDelivery`). An exhausted budget keeps the `HTTP <status>: ...` / `Connection failed ...` text `failover.py` classifies, so `call_llm_with_failover` still falls back once. Never add a retry loop to `caller.py`, `failover.py` or `http_pool.py`: the fallback model stays reserved for a provider that is actually down.

## Provider Rules

- Runtime provider config comes from `llm_model_dao` / `LLMModelRecord` rows, not direct env vars: provider, model, encrypted API key, base URL, timeout, temperature, vision support, max output tokens.
- Providers must resolve through the current registry (including existing aliases). Unknown names raise `UnknownProviderError` before factory cache lookup or client construction; an explicit endpoint does not authorize an unknown name. Use registered `custom` for custom OpenAI-compatible endpoints. This fresh-only contract has no persisted-model migration lane.
- Preserve streaming normalization for tool-call ids, partial JSON deltas, usage chunks, reasoning/thinking fields, and provider-native message shapes.
- New providers should be added through `ProviderSpec`/registry plus a provider client class or explicit OpenAI-compatible mapping.
- App attribution is `attribution.py`: `OpenAICompatibleClient._get_headers` adds `X-OpenRouter-Title: settings.APP_NAME` on `openrouter.ai` hosts (by host, so `custom` provider rows count). OpenClaw guests hard-code `X-OpenRouter-Title: OpenClaw` for OpenRouter chat and ignore config headers, so no guest config key carries `APP_NAME`; do not invent one.
- Grok (xAI) is registered as `grok` (`xai` / `x-ai` / `x_ai` aliases) on the OpenAI-compatible protocol at `https://api.x.ai/v1`.
- ChatGPT subscription rows stay on provider `openai` with `auth_kind=chatgpt_subscription`. Tokens are Codex OAuth, not Platform API keys. Engine calls go through `create_fresh_llm_client_from_model` → Codex `/responses` with `chatgpt-account-id`. Stateless tool rounds replay `provider_items` (encrypted reasoning). Both subscription kinds build their client with `stream_only=True` (the Codex backend rejects `stream: false`): `complete` reads the event stream, and `OpenAIResponsesClient.stream` parses SSE directly for it.
- Three client entry points differ. `create_fresh_llm_client_from_model(model, timeout=)` (`utils.py`) first runs `ensure_fresh_pool_model` (refreshes a stale Grok or ChatGPT subscription token), then returns `(fresh_model, client)`; use it for any call that spends a pool row (`caller.py`, `router.py`, heartbeat, background guard, supervision reminders) and keep the returned model. `create_llm_client_from_model(model)` is the cached constructor for an already-fresh row (it does not refresh, and a ChatGPT row gets the Codex Responses client); the enterprise key test uses it for an existing ChatGPT row. `create_llm_client(provider=, model=, api_key=, base_url=)` (`factory.py`) takes explicit credentials and knows nothing about pool rows or subscriptions.
- `ProviderSpec.default_model` is the current flagship API id for the admin Models form (e.g. `grok-4.8`, `gpt-6.2-sol`). Local runtimes may leave it unset.

## Tool Loop

- Final assistant text is expected through the `finish` tool. Do not bypass finish-protocol enforcement casually.
- Tool calls are sanitized before appending back into model context.
- Tool execution goes through `app.services.agent_tools.execute_tool(...)`.
- Vision/screenshot injection is conditional on the selected model supporting vision.

## Tests

- Existing focused coverage includes `tests/test_finish_protocol.py`, `tests/test_llm_client_contract.py`, `tests/test_llm_registered_provider_contract.py`, and `tests/test_llm_streaming_normalization.py`.
- Add fake HTTP/stream parser tests for provider client changes. Retry behavior is tested against every provider for both call styles with `tests/llm_retry_fakes.py` (scripted responses, `install_retry_policy(jitter=)` records waits instead of sleeping and fixes the random draw); never sleep for real or call a live provider. Circuit behavior uses `install_provider_health` (a tracker on a hand-advanced `FakeClock`) and `health_model` (a row with its own id, so circuits do not leak between tests); any test that opens a circuit on the shared tracker must reset it with `reset_provider_health()`.
- Add pair-integrity tests when changing `convert_chat_messages_to_llm_format` or `truncate_messages_with_pair_integrity`.
