# app/services/realtime_runtime

This package handles cross-process realtime routing. Local WebSocket connection ownership still lives in `app/api/websocket.py`.

## Routing Model

- `RealtimeRouter` (`router.py`) uses Redis presence and Pub/Sub under the `realtime:ws` prefix. `contracts.py` holds the fixed envelope and presence shapes; websocket event payloads stay unconstrained JSON.
- Messages go to the matching local sockets concurrently (`fanout.py`, at most `LOCAL_FANOUT_CONCURRENCY` in flight) while the Redis presence lookup runs alongside; remote instance channels are published after both finish. The event is serialized once per delivery (`encode_event_text`). The receiver (`deliver_pubsub_message`) uses the same fan-out, still one pub/sub message at a time in arrival order; never dispatch pub/sub messages as separate tasks, which would reorder chunks.
- `INSTANCE_ID` is part of routing identity. Set stable ids for multi-worker deployments that need predictable audit/routing behavior.
- Presence TTL is 180 seconds. Stale Redis connection ids are cleaned opportunistically during presence listing.

## Lifecycle And Readiness

- The lifecycle owner is `app.runtime.lifecycle` (the `api` role calls `realtime_router.start`, shutdown calls `stop`), not `app.main`. A start failure is reported and logged, and the process stays not-ready.
- `RealtimeRouter.ready` feeds `/api/ready` (`runtime/readiness.py`) only for the `api` role. It needs a started router, a live subscriber task, an **acknowledged** subscription and a connected Redis connection.
- `RealtimeRouter.start(deliver_local, on_resubscribe=None)`: after every subscribe acknowledgment except the first (counted per `start`, across reconnects) the subscriber loop awaits `on_resubscribe` before the next event; a hook failure is logged and never drops the subscription. `app.runtime.lifecycle` passes `ConnectionManager.close_local_connections`, which closes local chat sockets with `RESUBSCRIBE_CLOSE_CODE` (1012, never 4001/4003) so clients reconnect and refetch history. There is no resync event type.
- `subscription.py` `AcknowledgedPubSub` clears `acknowledged` on health-check disconnect, `on_connect` and `_reconnect`, because redis-py retries reads inside its own reconnect boundary. The subscriber loop sets it only from a `subscribe` message for this instance's channel, and clears it on `unsubscribe`, loss and shutdown. Do not set readiness from a successful `subscribe()` call.

## Shared Chat Delivery

- `chat_authorization.py` `authorize_chat_delivery` runs for every local send and returns a `DeliveryVerdict`. Ordinary sessions are `ALLOWED` with no work. `read_shared_acl_version` reads the agent ACL version once per delivery, before any socket authorizes and only when a target is the shared session, and the caller passes it as `acl_version`; ordinary sessions do no ACL read. A shared-session socket needs its `ChatTicketBinding` for that exact agent and session (`NOT_VIEWER` otherwise, counted nowhere) and a binding inside its own `auth_deadline` (`chat_tickets.is_expired`, checked per socket before the cache; `UNAUTHENTICATED` otherwise).
- A positive decision is cached on the socket for `DELIVERY_AUTHORIZATION_TTL_SECONDS` while the ACL version is unchanged. Without one, the socket joins the cold decision for its key: the binding's user, tenant, agent, session, `auth_generation` and `membership_generation`, plus the ACL version. A process runs at most one decision per key: a tracked task (`shared-chat-authorization`) started in an empty `contextvars.Context()`, so it never joins a connection its first waiter holds, that runs the deadline-free `chat_tickets.authorize_identity` (fresh principal, identity and membership generations, `check_agent_access(..., fresh=True)`) and `authorized_session` on one `connection_ctx()` checkout. No more than `LOCAL_FANOUT_CONCURRENCY` cold decisions run at once across all deliveries. Only `ALLOWED` is cached; refusals and skips never reach `access_cache` or the socket cache.
- A caller waits for a decision only until a deadline counted from the decision's start, not from its own event: `CHUNK_AUTHORIZATION_WAIT_SECONDS` (2.0) for chunks, `DEFAULT_AUTHORIZATION_WAIT_SECONDS` (5.0) for other events and `TERMINAL_AUTHORIZATION_WAIT_SECONDS` (15.0) for `done`/`error`, resolved per message by `router.resolve_authorization_wait` beside `resolve_send_timeout` and kept apart from the send bounds. A waiter that gives up gets `SKIPPED` and never cancels the decision (`asyncio.wait`); if the decision later allows, it still fills that socket's cache, and the events in between skip at once because their deadline has already passed. A healthy 1.3 s check delivers every chunk in order. Never wrap `authorize_chat_delivery` in a timeout that cancels it: the discarded decision is restarted by every later chunk and cancelled again. Never give each event a fresh wait: one slow decision would then stall the serial subscriber for every chunk.
- Only 401 (`UNAUTHENTICATED`, close 4001) and 403 or 404 (`FORBIDDEN`, close 4003) mean revoked. Everything else is transient and `SKIPPED`: any other status, including the retryable 423 `transfer_cleanup_pending` and 503, `DbOverloadError`, psycopg `PoolTimeout`, Redis errors and `OSError` (`TRANSIENT_AUTHORIZATION_ERRORS`), and an unexpected exception (also reported). A transient failure skips only that event for that socket, is never cached and leaves the socket open. Never close a socket on any `HTTPException`: the web client never retries a 4003, so 423 must stay a skip.
- Both paths run the same check with the same wait: the publisher in `RealtimeRouter._deliver_local` and the receiver in `api/websocket.py` `ConnectionManager.deliver_pubsub_message`. Keep both call sites; do not move authorization to the publisher. The subscriber loop still awaits each pub/sub message in arrival order, without per-message tasks.
- A revocation goes to the socket owner through `SendObserver.refused(agent_id, websocket, close_code)`. `ConnectionManager.refused` withdraws the socket synchronously with the same steps as an eviction (below) and closes it with 4001 or 4003 from one owned task in `ConnectionManager._eviction_tasks` (presence removal, then the close, each under `EVICTION_CLOSE_TIMEOUT_SECONDS`). A socket already withdrawn or no longer listed is left alone, so refusal, eviction and `disconnect` are idempotent in any order. Never await that close inside a delivery or `fan_out`.
- `RealtimeRouter.stop` cancels and awaits pending decisions (`cancel_pending_decisions`) after the subscriber, so none still holds a pool checkout when the lifecycle closes the pool.
- `route_message(send_timeout=)` bounds only each `ws.send_text`. Every send has a bound: chunks use `CHUNK_SEND_TIMEOUT_SECONDS` (publisher and receiver), other events `DEFAULT_SEND_TIMEOUT_SECONDS`, and `done`/`error` the longer `TERMINAL_SEND_TIMEOUT_SECONDS` (`resolve_send_timeout`), so one stalled socket cannot hold the serial subscriber loop. Never put a deadline around `send_to_session` or `route_message` themselves: cancelling routing skips remote instances.
- Stalled sockets are evicted. `ConnectionManager` is the `SendObserver` (`contracts.py`) passed to `route_message(observer=)` and used by `deliver_pubsub_message`: a send that times out counts against the socket, a successful send from either path resets the count, and other send errors do not count. At `STALLED_SEND_EVICTION_THRESHOLD` (3) consecutive timeouts the manager evicts the socket synchronously, before any await: it leaves `active_connections`, `is_live` turns false so a delivery whose snapshot still holds it skips it right before the send, `websocket.state.realtime_connection_id` is cleared so the handler's presence refresh cannot re-register it, and the presence id is hidden from `get_active_session_ids`/`is_user_viewing_session` until Redis removal finishes. One owned task in `ConnectionManager._eviction_tasks` then removes Redis presence (`unregister_connection_id`) and closes with `EVICTION_CLOSE_CODE` (1013, reconnectable; never 1012/4001/4003), each step under `EVICTION_CLOSE_TIMEOUT_SECONDS`; `drain_evictions()` awaits eviction and revocation closes alike. Never await `ws.close` inside a delivery or `fan_out`. Eviction and `disconnect` are idempotent in either order. The router keeps no socket state.
- `route_message` returns a `RoutingOutcome` (local targets, delivered, failed, evicted, skipped, remote instances, remote publish errors); `publish_chunk` returns it, or `publication_failed=True` when routing raised. `skipped` counts deliveries skipped by an expired authorization wait or a transient failure. `dropped` means a target was lost (failed, evicted, skipped, remote publish error or raised publication); a revocation, a socket that is not a viewer or no listener at all is not dropped. The streamer counts dropped chunks in `TurnTimeline.chunks_dropped`, emitted on the per-turn `[TurnTiming]` line next to `chunks_published` and `slowest_chunk_ms`.

## Editing Rules

- Do not move local in-memory WebSocket connection state into this package without redesigning `app/api/websocket.py`.
- Do not create ad hoc Redis clients for realtime paths. Use the router and `get_redis()`, and keep startup and shutdown in `app.runtime.lifecycle`.
- Preserve JSON event shapes used by websocket clients and trigger notifications.
- Treat Redis failures as cross-process delivery failures; do not let them corrupt local connection state.
- Tests: `tests/test_realtime_contracts.py` (routing outcome, skipped counted as dropped, refusals handed to the observer, remote publish errors, stateless router, 1013 bounded eviction close, 1012 resubscribe), `tests/test_realtime_readiness.py`, `tests/test_shared_chat_realtime.py` (binding, fresh principal, revoked receiver closes 4003), `tests/test_chat_delivery_authorization.py` (cache, verdict mapping, never-cached failures, decision cap), `tests/test_chunk_live_delivery.py` (slow-but-healthy authorization/Redis, shared decisions on one fresh checkout, waits counted from the decision start, a late allow filling the cache, revocation and transient skips, decisions cancelled by `stop`, stalled socket, bounded stream drain, eviction on publisher and receiver paths, stale snapshots), `tests/test_websocket_failure_lifecycle.py` (presence stays withdrawn after eviction or revocation, owned idempotent 4001/4003 close, receiver transient skips, quiet handler error paths, idempotent disconnect), `tests/test_chat_tickets.py` (deadline-free `authorize_identity`), `tests/test_openclaw_gateway_stream.py` and `tests/test_turn_timing.py` (`chunks_dropped`).
